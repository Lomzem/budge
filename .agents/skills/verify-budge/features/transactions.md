# Transactions and the Transaction dialog

Enter, edit, categorize, clear, approve, and delete movements of money in an Account or across all of them.

## Sub-features

- `txn-create`, `txn-cancel`: save a new Transaction or discard a draft.
- `txn-edit`, `txn-clear`, `txn-delete`: persisted edits, bank confirmation, and removal.
- `txn-categorize`: change one Transaction's Category or Transfer in place (`transactions.categorize`), leaving its approval as it was.
- `txn-select`: check rows across Payees, or some rows of one Payee, then give them all one Category (`transactions.categorizeMany`), optionally approving them too, or approve only them; Undo puts back rows still as that action left them (`transactions.undoCategorizeMany`, `transactions.unapprove`); changing a row the action touched ends its Undo offer, and a save that lands after the person changed the selection leaves the newer selection, focus and count line alone.
- `txn-payee-groups`: `Group by Payee` heads the shown rows by their Payee (its stored identity, never its name), so the visits of one Payee can be read by date and amount and picked at once, less the exceptions, through `txn-select`.
- `txn-list`: paginated Account and Accounts-page views; Uncategorized and Unapproved counts.

## How to get to it (user POV)

- The Accounts Section (`/accounts`, heading `Accounts`, with All Transactions below the phone Account list) or any named Account (`/accounts/<id>`) through the sidebar, the Accounts page, or the phone tab bar.
- Choose `Add Transaction`, or a row button named `<Payee>, edit Transaction on …`.
- The dialog asks Account, Date, Payee (suggesting saved Payees), Direction, Amount, then Category or Transfer and Memo. Its body scrolls under a sticky footer that holds the error line and Save, so Save and errors stay on screen in a long form; every form dialog uses that footer. On phones the footer's buttons share rows, the primary one last: an Unapproved Transaction at 320 px shows Delete (red tint, confirms first) beside Approve, then Save across the width.

## Gotchas

- **Manual drive:** unfiltered lists put Unapproved Transactions first and load 50 per page via Show more. Above the table, `Approve all N` approves at most 1,000 at a time; with more, the button reads `Approve 1,000`. Approve inside Edit Transaction leaves balances unchanged; desktop row Approve is also available. The Budget's `Needs you` chips for Uncategorized and Unapproved land on this list already filtered (see [search.md](search.md)).
- **Manual drive:** a line above the table reads the result, naming a Status or Uncategorized filter and saying `matching` for any other (`N Transactions`, `9 Uncategorized Transactions`, `3 matching Unapproved Transactions`, `2 Transactions the bank changed`, `… shown, more below`, `No Transactions match.`, `No bank changes wait on you.`) at a fixed height. Filters live in the URL (`q`, `account`, `category`, `status`, `payee`, `from`, `to`), so reload and Back keep them; malformed values are ignored, and an `account`, `category` or `payee` the filter menus don't offer is dropped from the URL before anything loads (`search/filters`). Status `Bank changes` lists every Transaction whose Bank Row changed or vanished (see [bank-changes.md](bank-changes.md)). After Save or Delete in the dialog, focus returns to the edited row, else the row now in its place, else `Add Transaction`, and the live region names what happened (`Transaction saved`, `Transaction deleted`). `Show more` focuses the first new row in the shown order (by Payee when grouped).
- **Manual drive:** in a Split, focusing an empty line's amount fills it with what is left of the total.
- **Manual drive:** check Payee Category recall and lookup/loading/failure states using [payees.md](payees.md). A Starting Balance keeps its Account, has no Payee, and cannot Split or become a Transfer. A Date before cutover must fail with `Budge starts on the cutover date; pick a later date.` and save nothing.

- Amounts follow the selected Direction; changing a field without Save is not persistence.
- Reconciled rows restrict edits until Unlock. A seeded list may not exceed a page: report pagination blocked if Show more cannot be reached with current data.
- **Manual drive (selection):** each row's first cell holds a checkbox named `Select <Payee>, <date>`. While any row is checked, the count line sticks to the top of the page, reads `N selected` with `Clear`, and holds the bulk picker (`Categorize`) and `Approve N selected` (`Approve N` below `sm`); what scrolls into view stops below it. The selection belongs to one register: opening another Account starts an empty one. Once a changed search or filter (including the Account filter) has loaded its rows, checked rows still shown stay checked and the rest are unselected, with `N selected Transaction(s) left the list and was/were unselected.` under the bar and in the status until the selection next changes. Bulk actions act only on shown, checked rows. Transfers and Splits keep their Categories (a note under the bar names them) and the server refuses them; at most 250 Transactions are categorized at once (`BULK_CATEGORIZE_LIMIT`, checked by `capacity:check`), and more shows `Categorize at most 250 at once.` Bulk categorize never changes a Payee's remembered Category. Undo restores only rows still as the action left them and focuses the first restored row in the shown order; a row changed since keeps its change, and editing, approving, unapproving or categorizing a row the action touched ends the Undo offer. After Undo the count line reads `N Transactions put back.` (or `N back to Unapproved.`); a row whose earlier Category was deleted keeps the bulk Category and is named, e.g. `3 Transactions put back. 1 kept Dining Out because its earlier Category was deleted.` A bulk action that finishes after the selection was cleared, changed or rescoped saves but leaves the newer selection, focus and count line alone.
- **Manual drive (Group by Payee):** the `Group by Payee` button (icon only below `sm`) sits beside the Approve button and keeps its state in the URL as `group=payee`, which is not a filter, so turning it on or off keeps the selection. Grouped, each section (`Unapproved`, `Approved`, or the one filtered list) holds one row group per Payee, ordered by name, then `Transfers`, `Starting Balance` and `No Payee`; rows keep their date order inside a group. The Date column goes and each row's edit button reads its long date (its name still starts with the Payee), and the column header reads `Date`. A group's checkbox is named `Select the N <Section> shown from <Payee>` and covers only the rows loaded on the page, never a Payee's unseen history; `Show more` adds to the groups. It never chunks past the 250 limit. Grouping changes no Payee and merges no names: two Payees whose names differ by one character stay apart.
