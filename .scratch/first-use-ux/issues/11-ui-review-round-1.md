### Known limitations, accepted/deferred items and verification gaps

These are neutral review inputs, not waivers. Judges assess user impact and severity on their merits. Required unverified cells leave assessment provisional and the gate incomplete; deterministic tests cannot substitute for missing experience evidence.

- **G1 — Plaid sandbox/fake boundary.** `budget-with-accounts` has a sample Sandbox-labelled connection with no login; `bank-sync` uses invented tokens that cannot decrypt, and the managed local app has no Plaid credentials. Real Connect, actual bank suggestion, successful real Link/reconnect, real post-repair sync and automatic arrival cannot be established. The unavailable-service notice also masks the missing-cutover notice and Connect becoming enabled. Do not introduce real credentials/data. `plaid/sync-waiting` and `plaid/superseded-sync` answer at the browser boundary; fake Link is also labelled. They prove presentation/ownership, not actual added Transactions or Plaid behavior. Receipt arithmetic is covered by fake-Plaid server tests, not this browser run. Webhook and daily sync return no receipt by design: no caller waits; their visible effects are freshness, problems and New bank Accounts. Real automatic delivery remains unverified, outside the synthetic review environment.
- **G2 — Manual state coverage.** Maintained journeys do not exhaust blocked/stale repair, every unsafe Undo refusal, source-evidence delay, recall/list loading/failure, failed inline save, long names or all themes/input/viewport combinations. Judges must use existing boundary-hold patterns and UI-created synthetic data where possible, or identify the exact missing task/state and setup impediment. No production/test code edits or throwaway deployed endpoints are authorized by this brief. The synthetic straddling-Transfer setup in ticket 03 was a deleted throwaway mutation, not an available fixture. Positive missing-cutover import error is unreachable through normal setup routing; do not force it as behavior proof. Accounting limits/stale/refusal invariants have owner tests; do not call them browser-verified. The accepted layout guard credits navigation-triggered pending requests through first result; judges still assess slow-network loading and visual stability directly.
- **G3 — Deleted-Category Undo sentence.** Ticket 07 owner test covers restoring eligible parts when an earlier Category was deleted; no journey covers the visible sentence. Manual candidate: categorize rows whose earlier Category is an ordinary Category, leave Undo available in its register scope, delete that Category through Categories into another destination, return and Undo. Observe whether the offer survives and whether the count names kept rows truthfully; if this state cannot be reached, record the gap rather than infer from the owner/type proof.
- **G4 — Earlier-Transactions notice.** After remapping, the notice cannot be dismissed even when history rightly belongs in the old Account. It clears only when the relevant old Transactions move or disappear; the source checks at most 100 Bank Rows outside the current Account. `accounts/setup-correct` exercises the notice/link/persistence; judge its burden and trust implications.
- **G5 — Pending search selection.** A row checked while a typed search is pending is cleared when that search applies (300 ms pause observed in ticket 08). Accepted from ticket 07; maintained journey now waits for the narrowed list before checking. Manually reproduce typing then immediately checking a still-visible row; assess surprise/control rather than assuming safety makes it good UX.
- **G6 — Superseded success.** A successful card operation finishing after a newer operation leaves no visible trace of its own; current server state/freshness/sections may reflect it. A superseded failure remains a problem. `plaid/superseded-sync` proves current behavior; assess whether silence confuses the task.
- **G7 — Changed/removed Bank Row counts.** Deferred: only added/matched/held are counted. Per-row applied/no-op/flagged/removed outcomes would need new server tracking and capacity work. Do not mistake omitted changes for additions or an unchanged budget; assess whether present copy is truthful for scoped feedback.
- **G8 — Dev-server font-loading race.** Ticket 04 deferred to these judges: on a full dev load Atkinson can arrive during `font-display: optional`, narrowing bold phone tab labels and triggering a shift; production-build runs had not shown it. Inspect full loads and resize/slow loading, not only tab navigation. Ticket 09 also found a route-induced uncached font refetch and moved fake Link routing until after page load. Keep the layout guard; label the actual serving mode and separate these reproductions. No production claim follows from a passing dev journey or historical production run alone.
